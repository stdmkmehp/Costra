## 🎯 今日核心事件

### 1. D-015 触发词词典简化 · respond-round-N ↔ revise-round-N 合并（09:24）

**Human 指令原文**：
> "revise-round-1 和 respond-round-1 合并，不再做区分，功能都是改代码+回执，允许 agent 对某些 issue 有异议，并在回执内提出异议，但如果异议被 review-agent 拒绝后仍然要以 review-agent 的意见为主。"

**背景**：
COSTRA-101 Review-Tech Round 1 REVISE 落地后，Human 询问 `respond-round-1` 与 `revise-round-1` 差异，首次暴露双触发词的结构性分裂：
- 流程割裂：异议表态 vs 代码修复是同一思考过程的两面，强行拆分导致"有争议就先别改"成默认，拖慢节奏
- 决策成本转嫁 Human：Human 需预判"该先表态还是先改"，本应由 Agent 自判
- 仲裁链路歧义：respond-only 模式下 Agent 可能卡在"表态完但没改"的悬停态
- 触发词膨胀：D-011/D-013/D-014 已引入 12+ 词，继续扩不可持续
- 与 D-011 语义冲突：D-011 自动循环前置条件 4 禁止 P0 反驳，respond-only 天然产出反驳，结构上把 Agent 推出自动循环

**落地决策**：
1. **废弃** `respond-round-N`，Orchestrator 收到后自动映射为 `revise-round-N` 并向 Human 提示
2. **统一** `revise-round-N` 语义为"回执 + 修复 + 可表达异议"三合一
3. **新增异议仲裁链路**：Agent 反驳 → Round N+1 Review-Agent 二裁 → 撤回 / 驳回；驳回后 Agent 必须修复；二次反驳自动 ESCALATE
4. **铁律落定**（Human 明文）："如果异议被 review-agent 拒绝后仍然要以 review-agent 的意见为主。"
5. **D-011 自动循环前置条件 4 改写**：首次反驳不中断循环，Review-Agent 二次驳回 + Agent 再拒才 ESCALATE（让"允许异议"与"自动推进"共存）
