### 1.2 Step 1 文档校验证据（2026-05-02 19:46~19:52）

基于以下证据源：
- `/Users/weizhao/.codebuddy/plugins/marketplaces/codebuddy-plugins-official/plugins/plugin-dev/skills/agent-development/SKILL.md`
- `/Users/weizhao/.codebuddy/plugins/marketplaces/codebuddy-plugins-official/plugins/plugin-dev/agents/agent-creator.md`

- 现有 subagent 样例穷举（`find /Users/weizhao/.codebuddy/plugins/marketplaces/ -name "*.md" -path "*/agents/*"`）

**新事实**：
1. **CodeBuddy 100% 支持 subagent 工具白名单**（frontmatter `tools` 字段硬隔离）
2. **`tools` 省略 = 全工具访问**（含 Write / Edit / MultiEdit / Bash / delete_file / execute_command）
3. **`tools: ["Read", "Grep", "Glob"]` = 物理强制只读**（审查 subagent 绝对无法调 Write · 不是靠 prompt 纪律）
4. **载体机制**：必须放在插件结构内 · `.codebuddy-plugin/plugin.json` + `agents/*.md` · CodeBuddy 自动发现
5. **Reload**：`/reload-plugins` 热加载 · 不用重启 IDE
6. **`permissionMode` 字段存在**（样例：`weixin-minigame-helper` 用 `default`）· 但官方 agent-development SKILL 没给完整取值列表 · 推测含 `default / acceptEdits / bypassPermissions / plan`

### 1.3 颠覆性影响

- **v1.0 §2.1 / §3.2 / §6 Q3 彻底改写**：工具白名单不是"未来再升级"· 是**现在就可用**
- **§3.5 审查 subagent 无写权**：从"纪律约束"升级为**"物理强制"**
- **I-oneshot-write-violation** incident 类型：可从规约删除（物理不可能发生）
- **之前 card-reviewer-product-costra-126-r1 违规自写磁盘事故**：在新机制下**物理不可发生** · 该事故成为"老机制已废止"的活证据

## 2. Human 决策（Q-A ~ Q-D · 2026-05-02 19:53）

### 2.1 Q-A · 插件结构位置 → **选 (a1)**

**决策**：Costra 项目根直接做成 CodeBuddy 插件。

**落地**：
- 在 Costra 项目根新建 `.codebuddy-plugin/plugin.json`（插件清单）
- 在 Costra 项目根新建 `agents/` 目录（存放 10 个 subagent 定义）
- 两个目录**都跟随 git**（提交到仓库）
- 所有 Costra 项目的 Orchestrator 会话自动识别（CodeBuddy 启动时扫描工作区插件结构）

**放弃的选项**：
- (a2) `./.costra-agents/` 子目录插件（需每次 `--plugin-dir` 启动参数 · 对 Human 不友好）
- (a3) marketplace 发布（Costra 未上线 · 不适合公开插件）

### 2.2 Q-B · Subagent 命名空间 → **选 (b2)** `costra-` 前缀

**决策**：所有 Costra 装扮 / 审查 subagent 名字加 `costra-` 前缀。

**规划命名清单**（10 个）：

| 角色类型 | subagent name | 工作区 | 写权 |
|---|---|---|---|
| 被审装扮 | `costra-backend-dev` | `server/` / `api/` / `.team/members/backend-dev/` | ✅ |
| 被审装扮 | `costra-miniapp-dev` | `miniprogram/` / `.team/members/miniapp-dev/` | ✅ |
| 被审装扮 | `costra-pm-writer` | `docs/` / `.team/board.md` / `.team/backlog.json` / `.team/risks.md` / `.team/cards/` / `.team/members/pm-writer/` | ✅ |
| 被审装扮 | `costra-design-maker` | `design/` / `docs/design/` / `.team/members/design-maker/` | ✅ |
| 被审装扮 | `costra-devops-ops` | `infra/` / 各模块 `.github/workflows/` / `scripts/devops/` / `.team/members/devops-ops/` | ✅ |
| 被审装扮 | `costra-qa-planner` | `qa/` / `docs/qa/` / `.team/members/qa-planner/` | ✅ |
| 审查 | `costra-review-tech` | — | ❌ |
| 审查 | `costra-review-product` | — | ❌ |
| 审查 | `costra-card-reviewer-tech` | — | ❌ |
| 审查 | `costra-card-reviewer-product` | — | ❌ |

**理由**：避免与 CodeBuddy 内置 subagent（`code-explorer` / `code-reviewer` / `code-architect` / `debug` / `bugfix-verify` / 等）命名冲突 · 也避免与其他插件 subagent（如 `bmad-dev` / `bmad-review` / 等）冲突。

**放弃的选项**：(b1) 极简命名（撞车风险）

### 2.3 Q-C · permissionMode → **选 (c2)** `acceptEdits`

**决策**：所有被审装扮 subagent 用 `permissionMode: acceptEdits`。

**含义**：
- 文件编辑（Write / Edit / MultiEdit）**自动批准**（Human 不弹窗）· 避免 Human 因为每个写盘操作疲劳
- Bash 执行（`execute_command` / `Bash` 工具）**仍需 Human 批准**（危险操作把关）
- 体验：装扮 subagent 改 `miniprogram/` / `server/` 代码无感 · 但要 `npm run test` / `git commit` 之类仍要 Human 点头

**审查 subagent**：该字段对它**无意义**（因为 `tools` 只含 `Read/Grep/Glob/LS/WebFetch` · 根本没有 Write/Bash 工具可被触发 · permissionMode 不起作用）· 但为格式统一 · 审查 subagent 也填 `permissionMode: default`。

**放弃的选项**：
- (c1) `default` · 每次弹窗 · Human 会疲劳（一次 revise 可能写 10+ 个文件）
- (c3) `bypassPermissions` · 全自动 · 过度放权 · Bash 执行危险操作无人把关
- (c4) 不填 · 行为不确定

### 2.4 Q-D · description 触发示例 → **选 (d2)** 标准姿态

**决策**：每个 subagent 的 `description` frontmatter 字段**按官方要求写 2-4 个 `<example>` 块**。

**理由**：
- Costra 是 Orchestrator 显式 `task(subagent_name=...)` 调用 · 不依赖 CodeBuddy 自动推荐
- 但 `<example>` 块**也是文档的一部分** · 有助于未来阅读者（或并行 Orchestrator 会话）理解该 subagent 的使用场景
- 符合 CodeBuddy 生态既定规范 · 规约的"可移植性"更强

**格式**（每个 subagent 都按此骨架）：

```yaml
---
name: costra-{role}
description: |
  Use this agent when the Costra Orchestrator explicitly invokes it via task(subagent_name="costra-{role}") for {role} responsibilities.

  <example>
  Context: Orchestrator needs to implement backend API for COSTRA-104
  user: "run backend COSTRA-104 (Orchestrator internal dispatch)"
  assistant: "I'll spawn costra-backend-dev to implement the API."
  <commentary>
  Orchestrator explicitly dispatches backend work - spawn costra-backend-dev with full Context Injection (D-018 §3.3 §A~§H).
  </commentary>
  </example>

  <example>
  Context: Orchestrator needs to review backend delivery for COSTRA-104 R1
  user: "(Orchestrator internal) review tech COSTRA-104 round-1"
  assistant: "I'll spawn costra-review-tech for independent review."
  <commentary>
  All review work must go through spawn-based isolation (D-018 §3.5) - costra-review-tech has NO write tools by design.
  </commentary>
  </example>
tools: ["Read", "Write", "Edit", "MultiEdit", "Bash", "Grep", "Glob", "LS", "TodoWrite", "WebFetch"]
model: inherit
color: blue
permissionMode: acceptEdits
---

You are the Costra "{role}" persona executor...
```

**放弃的选项**：(d1) 极简 description（损失生态规范性）
