### §2.3 v3 新增前置项详解

#### ② runtime 实测前置（v3 新增）

**触发条件**：Step 3 根因分析涉及以下任一：

- 微信 SDK 启动时序（App.onLaunch / onShow / getStorageSync 时序）
- 渲染层时序（setData / WXML 渲染 / tabBar 渲染）
- 平台 API 运行时行为（wx.request / wx.getStorage / wx.login 等）
- 模块加载语义（JSON import / npm 包加载 / CommonJS require）
- 微信基础库版本相关行为

**v3 规则**：

- runtime 类 T2 卡 → DoD **必须**含 Human 模拟器实测 ≥ N 条断言
- Human 实测 5 条断言全 PASS = 终审绝对证据
- review-tech 纸面审 35/35 ≠ 假设正确（仅辅助证据）
- **→ D-022（review-tech 评分表 v2.0）** runtime 加载性 C8 维度

#### ③ 跨版本对照（v3 新增）

**触发条件**：Step 3 根因分析涉及以下任一：

- lib 版本升级 / 降级
- SDK 版本变更
- 工具链版本差异（Node.js / TypeScript / 微信开发者工具）
- 微信基础库版本（2.32.x vs 3.x.x vs development）

**v3 规则**：

- 跨版本对照作为运行时根因诊断**标准前置**
- 至少测试两个版本（old vs new）
- 版本对照结论必须写进根因报告（L1~L4）
- 版本漂移是"规律性逃逸"信号 → 触发 FU-LIBVERSION-DEV-GUARD

### §2.4 例外列表（v3 E1~E4）

| 例外 | 条件 | 合规路径 |
|---|---|---|
| **E1** | 微小 typo 级（Human 一眼可见错别字 / 路径拼写）| Human 直接命令 "run agent fix-xxx" 跳过 Step 2~5 · 但走 Step 6 |
| **E2** | 回归到已知 open FU（同族完全重叠）| 直接派"认领 FU-xxx"卡 · 跳过 Step 2~3 重复分析 |
| **E3** | Human 主动下令跳过 | Human 明文"跳过根因分析 · 直接按方案 X 实装" · Orchestrator 记录 |
| **E4（新增）** | Human 默示/明示接受 Orchestrator 代职分析 | Orchestrator 代职分析 + Human 接受 → 合规 · Orchestrator 记录"Human 默示/明示接受代职分析"于 dispatch §0 |

### §2.5 反模式列表（v3 ABCD + E 新增）

| 反模式 | 描述 | 触发条件 |
|---|---|---|
| **A** | Orchestrator 自己分析根因（领域专家 ≠ Orchestrator）| Orchestrator 跳 Step 2~3 自己下结论 |
| **B** | 只给一个方案 | Agent 认为"显然应该这么修"但仍只列 1 方案 |
| **C** | 跳过根因直接派单 | Human 反馈问题 → Orchestrator 立即派单 |
| **D** | 根因报告只写一层 | 不分 L1~L4 四层 |
| **E（新增）** | Orchestrator 自行下结论而不前置实测 | Orchestrator 在 runtime 类问题上未要求 Human 实测就拍板版本升级 |
