# Costra (Cost + Track) - 微信小程序设计规范

## 1. 简介与系统背景
本文档用于记录 Costra 微信小程序的各项需求、设计决策和讨论结果。Costra 是一款主打极简主义、支持单人及家庭协作的记账应用。本文档作为前端开发工程师和 UI 设计师的协同基准。

### 核心系统背景：多账本与家庭逻辑
*   **默认单人账本**：每个用户注册后，系统会默认生成一个"单人家庭"及其对应的独立账本。
*   **多家庭协作**：用户可以创建新的"多人家庭"并邀请其他用户加入。一个用户可以同时存在于多个家庭（如：单人默认家庭、与伴侣的小家庭、与父母的大家庭）。
*   **账本隔离**：每个家庭都拥有一个完全独立的账本。用户在记录任何一笔支出时，都必须明确该笔记录归属于哪个账本（记账页默认带入当前查看的账本）。
*   **视图上下文**：整个小程序的数据展示（明细、统计）均受当前所选"账本"的全局上下文控制。

## 2. 视觉风格与主题
*状态：已确认*

**参考规范：** 
1. `.agent/rules/ui_ux.rule` (Apple 设计系统)
2. `WeUI` (微信小程序官方设计指南，用于标准化基础组件，如表单控件、对话框、提示等，以保证与微信生态的融合度)。

**核心决策：以 Apple 极简设计风格为主导，在基础组件交互上兼容 WeUI 标准。**
应用程序将在视觉排版、颜色和空间感上完全采用 Apple 设计哲学（高质感、极简、数据导向），但在如 Picker（选择器）、Toast（轻提示）、ActionSheet（操作菜单）等原生组件层面，合理吸收 WeUI 的交互逻辑，确保在微信环境内的可用性和开发效率。

**关键执行规则：**
1. **二元色彩基调：** 背景颜色严格在油墨暖黑 (Warm Ink: `#1c1b1a`) 与暖灰白 (Bone White: `#f1f2ec`) 之间交替。该搭配既保留了极简的高级感，又为家庭记账注入了温润的质感。
2. **原生强调色 (WeUI)：** 放弃 Apple Blue，全面拥抱微信生态原生交互色。主行动按钮 (CTA) 采用微信品牌绿 (`#07C160`)，文字链接采用微信标准蓝 (`#576B95`)，以实现小程序环境下的沉浸感与信任感。
3. **排版驱动层级：** 遵循视差缩放原则使用字体。极紧凑的标题行高（如 1.07）和负字距，抛弃分割线。
4. **扁平与克制的深度：** 极少使用阴影，若使用则为 `rgba(0, 0, 0, 0.22) 3px 5px 30px 0px`。
5. **毛玻璃导航：** 顶部导航栏和底部 Tab 栏将使用半透明浅色毛玻璃效果 (`rgba(255,255,255,0.85)` + blur)，保持空间的通透与呼吸感。
6. **全局空状态 (Empty State)：** 严禁使用任何卡通、插画或大面积缺省占位图。当列表无数据时，仅在页面正中央展示一行极简的中灰小字（如 `本月暂无收支记录`），保持绝对的高级与冷峻感。

## 3. 核心功能与页面结构 (TabBar)
*状态：已确认*

**底部导航 (TabBar) 结构：采用 5 Tab 中置式布局。**
*   **外观：** 采用浅色半透明毛玻璃材质 (`rgba(255,255,255,0.85)` + blur)，以完美融入暖灰白的主背景，保持视觉的连贯与呼吸感。图标及文字默认状态采用浅灰色，选中状态采用油墨暖黑 `#1c1b1a` 或微信绿 `#07C160`。
*   **Tab 项分布：**
    1.  **明细** (Ledger/Activity)：查看日常流水。
    2.  **统计** (Statistics/Charts)：数据图表与趋势分析。
    3.  **[+] 记账** (Add Expense)：放置在正中间的特殊高亮按钮，承载核心记账动作。
    4.  **家庭** (Family)：家庭协作空间，共享预算与结算。
    5.  **我的** (Profile)：个人设置与系统功能。

## 5. 技术架构约束
*状态：已确认*
设计方案必须完全兼容且易于落地于当前的**微信原生小程序 (Native MINA)** 架构：
*   **开发语言：** TypeScript
*   **页面结构：** WXML
*   **样式：** WXSS
*   **页面配置：** JSON
*   **设计原则：** 避免需要极其复杂的自定义渲染或突破原生小程序限制的设计（如复杂的 3D 渲染、脱离原生生命周期的诡异动画）。底部导航栏应尽量兼容微信原生 `tabBar` 或常规的 `custom-tab-bar` 实现。弹窗优先考虑基于 `<view>` 或 WeUI 扩展组件构建的标准底部/居中交互层。

## 6. 页面详细规范
*状态：持续更新中*

### 6.1 登录页 (Login)
*   **页面定位：** 去除冗余的 onboarding 动画，追求极致的加载速度和品牌第一印象。
*   **背景视觉：** 油墨暖黑 (`#1c1b1a`) 或 暖灰白 (`#f1f2ec`) (高定质感底色)。
*   **核心内容排版：**
    *   **中心视觉区 (Center)**：展示"Costra"品牌 Wordmark/Logo。
    *   **趣味/深度文案 (Dynamic Text)**：在 Logo 下方，显示一行极具 Apple 排版风格的文字（如 SF Pro Text, 14px/17px, 弱化对比度的颜色如 `rgba(255,255,255,0.48)` 或 `rgba(0,0,0,0.48)`）。该文案每次进入时从预设文案库中随机抽取一句（如："掌控数字，还是被数字掌控"、"每一笔支出，都在为你想要的世界投票"）。
*   **交互控件：**
    *   **登录按钮：** 仅保留一个核心 CTA —— "微信一键登录"。复用 WeUI 标准组件，采用微信品牌绿 (`#07C160`) 背景，标准圆角 (8px)，位于页面偏下方。
*   **合规组件：** 不在登录主界面展示隐私协议勾选框，保持绝对的极简。相关合规动作在点击登录按钮后通过微信官方的原生授权弹窗/流程解决。

### 6.2 明细页 (Ledger / Activity)
*   **页面定位：** 小程序首屏，展示当月财务概况与日常流水。包含多账本（单人/家庭）切换入口。
*   **背景视觉：** 采用暖灰白 (`#f1f2ec`) 背景。通过抛弃暗黑模式，以大面积的温润高定浅色底营造"家庭纸质账本"的安心感与生活气息。
*   **顶部导航栏 (Navigation Bar)：**
    *   作为**账本切换入口**（低频但必备）。将当前账本名称（如"我的账本"、"XXX的家庭"）置于微信原生导航栏中央，名称右侧附带极小向下箭头 `▼`。
    *   点击唤出标准底部 ActionSheet 或原生选择器以切换当前作用域账本。
*   **头部汇总区 (Header) - 数字震撼型：**
    *   **左上主视觉**：巨大的"当月总支出"金额（如 `56px SF Pro Display`, 字重 600，负字距，油墨暖黑 `#1c1b1a` 文字），给予强烈的视觉冲击。下方以较小字号（如 14px, 中灰 `rgba(28,27,26,0.48)`）跟随"当月总收入"与"结余"。
    *   **右上交互区**：包含两个控制维度的极简选择器（右对齐）。
        *   **时间维度**：年月选择器（如 `2026年5月 ▼`）。点击唤起底部日期滚轮。
        *   **成员维度 (仅限多人家庭账本显示)**：在年月选择器右侧，放置筛选胶囊按钮（默认文案 `全部 ▼`）。点击展开浮出式筛选面板（Expandable Filter Panel），覆盖在流水列表上方，不推挤列表。面板包含两个筛选维度：
            *   **费用性质**：三个互斥胶囊标签 `[全部] [个人支出] [公共支出]`，单选即生效。默认"全部"。选中态：油墨黑底 + 暖灰白文字（反转）；未选中：`rgba(28,27,26,0.06)` 底 + 油墨黑文字。
            *   **成员多选**：横向 4 列网格展示家庭 active 成员圆形头像（56rpx），最多 2 行（8 人）。选中态：`opacity: 1` + `#07C160` 绿色描边 + 右下角绿底白勾；未选中：`opacity: 0.35`。标题右侧有 `全选`/`取消全选` 文本按钮。
            *   **面板交互**：点击面板外区域自动保存并关闭（带 280ms ease-out 动画）。关闭时若无成员选中则自动回退为全选。面板背景与页面一致（`#f1f2ec`），底部圆角 24rpx，投影 `0 4rpx 24rpx rgba(28,27,26,0.08)`。蒙层 `rgba(28,27,26,0.06)`。
            *   **筛选按钮状态**：无筛选时浅灰底；有筛选激活时微信绿底 `#07C160` + 白色文字，显示筛选摘要（如 `个人 · 3人`）；面板展开时箭头旋转 180°。
            *   若当前为单人默认账本，则彻底隐藏此按钮。
*   **流水列表 (List)：**
    *   **分组标题 (Date Header)**：按日期倒序排列，包含日期与当日总收支。支持 **吸顶 (Sticky) 效果**。
    *   **条目设计 (List Item)**：极致精简。无卡片，无分割线。
    *   **信息颗粒度**：展示 `[极简单色二级图标] + [一级-二级分类] + [金额]`。
    *   **多人协作感知**：当处于多人家庭账本时，在左侧极简二级图标与右侧文字（分类名或备注）之间，**插入该记账人的极简 Mini 微信头像**（如 16px 圆形）。通过头像直观且优雅地区分开销归属，免去昵称备注系统的开发。该头像在任何筛选状态下（全部/仅自己/仅他人）均**常驻显示**，确保列表 UI 结构的绝对稳定和对齐。单人默认账本下隐藏该头像位。
    *   **备注逻辑**：有备注直接替换"一级-二级分类"组合（文字排在 Mini 头像之后）。
    *   **金额显示**：最右侧对齐，字体使用等宽数字体，确保小数点对齐。字号 21px，颜色为油墨暖黑 `#1c1b1a`。

### 6.3 记账交互动作 (Add Expense)
*   **唤起方式：** 点击 TabBar 中部的 `[+]` 按钮。进入全屏记账视图。
*   **背景视觉：** 采用与主界面一致的暖灰白 (`#f1f2ec`) 背景。
*   **交互与信息架构：**
    1.  **收支切换 (Horizontal Swipe Toggle)：** 抛弃静态的顶部分段控制器。整个分类网格区域支持**水平滑动 (Swipe)**。向左/向右滑动屏幕，即可在"支出"和"收入"两个面板之间平滑切换（类似微信相册的翻页体验）。页面顶部仅保留极简的页面指示器 (如两个小圆点) 或渐隐的文字提示，极致简约。
    2.  **双层分类网格 (Two-Tier Category Grid)：**
        *   **初始排版**：界面上方展示所有"一级分类"，下方展示所有"二级分类"。两部分通过略宽的留白或极浅的横线（油墨黑的 5% 透明度）隔开，暗示层级差异。网格严格遵循"一行 4 个"的布局。
        *   **色彩约束**：图标和文字底色均在暖灰白 (`#f1f2ec`) 背景上呈现。高亮选中状态采用明显的油墨黑 (`#1c1b1a`) 或微信绿 (`#07C160`) 加以强调。
    3.  **计算器动态弹窗 (Dynamic Keypad) 与分类交互联动：**
        *   当用户点击选中并高亮某个分类后，下半屏弹出自定义的数字计算键盘。
        *   **场景 A (点击一级分类)：** 该一级分类平滑移动至屏幕顶端；其下方按"一行 4 个"就地展开所属的二级分类；**未被选中的其他一级分类渐隐变淡 (Opacity: 0.2)**，形成视觉聚焦；系统**智能默认选中**展开后的第一个子分类。
        *   **场景 B (越级直选二级分类)：** 不触发一级分类的展开和反推。仅将被点击的二级分类高亮；**防遮挡逻辑**生效：若该二级分类位于下半屏，则整体分类网格向上滚动 (Scroll-to-view)，确保该图标移动至上半屏安全可视区（不被弹出的键盘遮挡），避免界面发生难以预期的巨变。
    4.  **算式展示逻辑 (Equation Display)：**
        *   用户输入时，金额显示区域直接展示计算过程（如显示 `12 + 8`）。
        *   **计算与完成解耦**：当输入算式后，键盘右下角的按钮显示为 `=`。按下 `=` 仅计算并展示结果（如 `20`），不直接保存记录。
        *   **完成记账**：按下 `=` 计算出结果后，该按钮文案会变为"完成"（微信品牌绿 `#07C160` 背景）。只有用户明确点击"完成"，才视为记账结束并保存。注：如果用户仅输入了纯数字（无加减过程），该按钮默认即显示为"完成"。
        *   **链式计算逻辑**：如果输入 `12 + 8` 后再次按下 `+` 号，系统先将前序结果计算出来，界面显示为 `20 +`，继续输入数字变为 `20 + 10`。此时右下角按钮重置为 `=`。
    5.  **账本归属与费用性质 (Ledger & Shared Attribution)：**
        *   **智能默认**：默认记入用户在明细页正在查看的账本。
        *   **费用性质标记 (仅限家庭账本的支出场景)**：当归属于多人家庭账本且当前为"支出"面板时，单行输入区的左侧增加一个极其轻量的滑动开关或极简文本按钮（如 `[ 个人支出 | 公共支出 ]`，默认公共支出）。用户可一键标记此笔费用是仅归属于自己的开销，还是家庭共同承担的开销。**注意：当切换到"收入"面板时，该开关彻底隐藏（不存在公共收入的概念）。**
        *   **弱化切换入口**：如果用户需要把账记到别的账本，仍可通过点击这行最左侧的极淡灰色小标签（如 `记入: 我的家庭 ▼`）来更换。右侧为占位较长的"添加备注..."文本框。
        *   **键盘无缝切换**：当用户点击"添加备注"文本框时，界面的上半部分保持不变，底部的数字计算键盘将无缝替换为系统自带的中英文键盘。输入完成后切回。
        *   **跨账本切换的动态表单响应 (Dynamic Form Reactivity)**：在记账页内切换账本归属时，所有与账本属性相关的 UI 控件必须具备即时响应能力。具体规则：当用户通过 `记入: ▼` 将账本从多人家庭切换为单人账本时，`[个人支出 | 公共支出]` 开关必须瞬间平滑隐藏（带 fade-out 动画）；反之，从单人切换至多人家庭账本且当前处于"支出"面板时，该开关需平滑浮现。任何时刻，表单状态都必须与当前选择的账本属性（单人/多人）保持严格一致，杜绝逻辑冲突。

### 6.4 统计页 (Statistics / Charts)
*   **页面定位：** 核心数据洞察，提供从宏观趋势到微观分类的完整财务报表。
*   **背景视觉：** 暖灰白 (`#f1f2ec`) 背景。通过极简排版和留白区隔模块，**坚决不使用**任何传统的彩色饼图或厚重的卡片背景。
*   **视图切换逻辑 (Time & Member Dimensions)：**
    *   **时间维度 (快捷切换与维度切换)**：页面顶部设有时间导航控制区。包含 `[<] 2026年5月 ▼ [>]`（点击中间唤起滚轮，点击左右箭头便捷切换前后月份/年份），以及右侧的 `[月度 | 年度]` 维度切换按钮（参考家庭页的做法）。
    *   **成员维度 (滑动切换 Swipe)**：对于多人家庭账本，将极具流畅感的内容区**水平滑动**交互让渡给"成员对比"。页面顶部设有极简的滑动指示器（如 `[ 全部 | 自己 | 成员A | 成员B ]`）。用户在数据区左右滑动，即可极速比对不同家庭成员的消费报表。该交互设计确立了成员比对优先于时间切换的用户痛点解决路径。
*   **月度视角 (Monthly View) 排版架构 (自上而下)：**
    1.  **宏观区**：巨大的"当月总支出"与"总收入"数字。附带极简的同环比提示（如 `↓ 12% 较上月`）。下方紧跟一条贯穿屏幕宽度的极简**单色折线图**（无坐标轴，仅展示当月每天的起伏趋势。**明确界定：此折线图为纯静态展示 Static Visual Trend，不支持手势长按和拖动查值，彻底将横向滑动交互让渡给成员切换**）。
    2.  **摘要区**：采用 2x2 或 3x3 的无边框网格平铺极限数据，如 `日均支出`、`最大单笔`、`单日最高支出`、`记账笔数`。使用中等字号数字+小号灰色标签。
    3.  **排行区**：一级分类金额排行榜列表。分类名下方带有 2px 的纯色进度条代表占比。
        *   **长列表省略逻辑 (List Truncation)**：为避免长列表造成的视觉疲劳，若一/二级分类条目过多（如超过 6 项），仅展示金额排名靠前的核心条目。列表底部以极简的灰色小字提示（如 `还有部分较小支出未显示...`），保持界面的绝对精简。
        *   **零值排除规则 (Zero-Value Exclusion)**：排行榜和手风琴展开的明细列表中，**严格排除金额为 0 的分类条目**。仅展示当期有实际消费记录的分类，杜绝 `购物 ¥0` 此类无意义条目占据屏幕空间。此规则同样适用于年度视角的排行区以及家庭页的分类下钻列表。
    4.  **下钻交互 (手风琴展开)**：点击排行区中的某个一级分类（如"餐饮"），该行向下原地展开，露出其下辖的二级分类统计列表的排行。二级列表同样适用上述的"长列表省略逻辑"。二级分类统计列表可以继续点开，该行向下原地展开，露出其下辖的二级分类明细的排行，同样适用上述的"长列表省略逻辑"。
*   **年度视角 (Annual View) 排版架构 (自上而下)：**
    1.  **宏观区**：巨大的"全年总支出"与"总收入"数字。折线图则变为展示**12个月份的宏观起伏趋势**。
    2.  **摘要区**：平铺年度极限数据，如 `月均支出`、`年度最大单笔`、`单月最高支出`、`全年最贵分类`。
    3.  **月度流水区 (年度特有)**：一个极简列表，从 1月 到 12月 垂直排列，单行展示该月的 `[月份] + [总支出] + [总收入] + [结余]`。点击单月可直接跳转/切换至该月的"月度视角"。
    4.  **排行区**：全年维度的一级分类金额排行榜（同样支持手风琴展开看二级分类排行，适用长列表省略逻辑，即仅显示排名靠前条目，其余显示省略提示；二级分类排行同样支持继续点开查看二级单笔的明细）。

### 6.5 家庭页 (Family / Collaboration)
*   **页面定位：** 当前账本的协作控制中心 (Dashboard)。基于当前选择的家庭账本，展示人、规则与公共收支的剥离。**顶部原生导航栏标题固定为"家庭"**。
*   **背景视觉：** 暖灰白 (`#f1f2ec`) 背景。
*   **单人用户落地页 (Solo User Landing)**：
    *   当用户仅拥有系统默认的单人家庭（无任何多人家庭）时，家庭页展示**转化引导态**而非空白：
    *   顶部仍显示个人家庭名称（如 `我的账本`）。**移除**成员与邀请区（单人家庭不支持邀请）。
    *   **公共/个人收支数据区简化**为类似统计页的摘要展示（仅展示个人本月总支出/收入/结余等核心数据）。
    *   在摘要数据下方，留出充足的呼吸空间后，居中排版一行极简的中灰小字引导文案：`财务独立，但不孤立。邀请伴侣或家人，开启清晰的共同记账。`（字号 14px，颜色 `rgba(28,27,26,0.48)`）。
    *   文案下方放置一个醒目的微信绿 CTA 按钮：`[创建家庭账本]`（`#07C160` 背景，白色文字，圆角 8px，宽度占屏幕 60%）。点击后进入创建家庭流程。
*   **多人家庭信息架构排版 (自上而下)：**
    1.  **家庭名称区**：顶部留白后，居中显示巨大的当前家庭名称（如 `史蒂夫的小家`，字号 28px，油墨黑）。
    2.  **成员与邀请区 (Avatar Row)**：
        *   在家庭名称下方，**横向平铺**家庭成员的极简圆形微信头像（与统计页的成员指示器风格保持绝对统一）。
        *   **横向溢出处理 (Horizontal Overflow)**：当成员数量超出屏幕可视宽度时（通常 > 5 人），采用**隐形横向滚动 (Horizontal Scroll-view with hidden scrollbar)** 处理。用户可手指水平拖拽查看更多成员，**绝对不允许换行**打断纵向瀑布流阅读节奏。滚动条不可见，保持极简。
        *   **已退出成员 (Departed Member)**：被移出家庭的成员，其历史流水数据保持不可变 (Immutability)，不做删除。但该成员的 Mini 头像在所有展示位（明细页列表、家庭页成员区、统计页指示器）统一变为**黑白灰度 + 半透明 (Opacity: 0.4)** 处理，点击无响应。在家庭成员区中，已退出成员排列在末尾（邀请 [+] 按钮之前），头像下方可选带极弱的 12px 灰色文字 `已退出`。
        *   **邀请机制**：在横排头像的最右侧，常驻一个淡绿色的 `[+]` 圆形按钮。点击后调用微信原生能力，发送家庭邀请卡片给好友。
        *   **管理机制**：对于该家庭的创建者，点击列表中其他成员的头像，会从底部弹出 WeUI ActionSheet，提供"移出家庭"等管理选项。
    3.  **公共/个人收支数据区 (Shared vs Personal Tracker)**：
        *   这是家庭页的核心数据区，用于彻底拆解"家庭总支出 = 公共支出 + A个人支出 + B个人支出..."，并附带垫付贡献和下钻分析。该区域上方提供时间导航区 `[<] 2026年5月 ▼ [>]` 以及 `月度 / 年度` 文本按钮切换全局时间维度。
        *   **全局占比视窗 (Segmented Bar)**：在区域顶部，放置一条贯穿的极简水平长进度条（如宽 8px，无边框）。将其按实际金额比例切分为若干段（分别代表公共、成员1、成员2等），使用不同深浅的单色块/微信绿进行视觉区分，给予用户一目了然的宏观分布体感。
        *   **数据明细列表 (Detail List)**：在进度条下方，按行垂直排列出对应的数据块：
            *   **公共支出行**：展示公共总金额。在其下方用极简的灰色小字展示**垫付贡献比例**（如：`史蒂夫付 ¥5000 / 爱丽丝付 ¥3000`）。
            *   **各成员个人支出行**：平铺展示该家庭内所有成员的个人支出总计，带有对应的 Mini 头像。
        *   **下钻交互 (Accordion Drill-down)**：列表的每一行均支持点击下钻。点击某一行（如"公共支出"或"爱丽丝个人"），该行向下原地手风琴式展开，展示该板块内**按金额高低排序的核心支出明细分类排行榜**（如：公共支出展开后显示 -> 1. 餐饮 ¥3000, 2. 房租 ¥2000...）。该排行榜适用统计页的长列表省略逻辑。

### 6.6 我的 (Profile / Settings)
*   **页面定位：** 用户个人中心、系统设置、数据概览及关于应用。
*   **背景视觉：** 采用与主界面一致的暖灰白 (`#f1f2ec`) 背景。
*   **信息架构排版：**
    1.  **顶部用户信息区 (Minimal Header)：**
        *   采用极简名片式布局。左侧放置极小的圆形微信头像（如 48px）。
        *   右侧对齐显示微信昵称（油墨暖黑 `#1c1b1a`，字号 21px，字重 600）。
        *   昵称下方显示极简的记账天数（如"已记账 120 天"），中灰文字，字号 12px。
        *   留出大量上部空白 (Padding-top)，不作喧宾夺主的设计。
    2.  **宏观数据总览 (Data Overview)：**
        *   在用户信息下方，横向平铺 2-3 个核心数据（如：总记账笔数、累计消费总额）。
        *   **设计手法**：保持背景透明（不加底层卡片），让数字自己说话。数字采用大字号等宽字体 (28px)，下方配以 12px 的灰色标签说明。各数据块之间用极其微弱的垂直短线或纯粹的留白隔开。
    3.  **功能列表 (Inset Grouped Menu)：**
        *   采用最新版 iOS / 微信 (WeUI) 的圆角分组卡片风格。
        *   卡片背景为纯白 (`#ffffff`)，圆角 12px。放置于暖灰白背景上，通过色彩微差形成自然边界，不使用阴影。
        *   列表项包含：导出数据、类别管理、家庭协作（置灰/带二期角标）、关于 Costra。
        *   列表文字左对齐，右侧保留系统自带的微小 `>` 灰色箭头图标，遵循用户最基础的导航直觉。
